Metric Suite Comparison: Tayer 2023 Legacy vs HydroFragments Refactor

No code-level detail. This report compares which metrics the old iRiverMetrics/Tayer-style workflow considered, which metrics the refactored HydroFragments repository keeps, changes, drops, or defers, and why those choices matter scientifically.

Old suite: legacy wide CSV metrics Updated suite: HydroFragments v1.2 contracts and registry Prepared from local repository evidence

Old Metric Logic

The legacy Tayer/iRiverMetrics workflow reports one wide row per date and section. It mixes context fields, raw wetted totals, patch-shape summaries, persistence summaries, and fragmentation ratios in the same table.

Main weakness: several ratios use the current wet surface itself as denominator. That makes metrics rise or fall partly because the denominator moved, not only because fragmentation changed.

Refactored Metric Logic

HydroFragments v1.2 shifts toward fixed denominators, explicit validity, dependency-gated channel/connectivity metrics, and tidy long output with flags.

Main strength: each metric row can carry its denominator, validity support, threshold, CRS, composite rule, dependency, and warning flags. That makes comparison safer.

Big Differences

  • Fixed denominators replace moving wet denominators. APSEC, LPI, MESH, and LPSEC use AOI or channel references rather than the wet patches currently present.
  • Pixel persistence becomes occurrence. The new occurrence metric uses valid observations as denominator, with a support floor, instead of treating every timestep equally.
  • Raw totals become support context. Wet area, wet length, wet perimeter, section area, and section length still matter, but mainly as denominators, metadata, or diagnostic context.
  • Dropped metrics are mostly dropped for circularity or weak independence. PF, PLF, AWMPA, AWMPL, and AWMPW no longer belong in canonical v1.2 output.
  • Channel and connectivity metrics are dependency-gated. LPSEC, inter-pool gap, realised connectivity, and TCF need drainage, graph, or fixed-node context; they should be skipped rather than faked when inputs are missing.

Legacy Metrics and Refactor Decisions

Legacy metric What it measured Refactor decision Why it matters
section_area_km2 AOI or river-section polygon area. Context Still essential as fixed reference area for APSEC, LPI, and MESH. It is not an ecological response metric by itself.
section_length_km User-supplied section or drainage length. Reworked Needed for LPSEC and channel spacing metrics, but the refactor requires a real, recorded channel reference rather than an ambiguous scalar.
wet_area_km2 Total wetted area in the section at a timestep. Support value Useful for audit and interpretation, but APSEC is safer for comparison because it normalises to fixed AOI area.
wet_length_km Total skeleton or pool length across wet patches. Support value Useful only when length extraction and channel reference are defensible. Refactor uses it through LPSEC or gap metrics, with caveats.
wet_perimeter_km Total wet-patch perimeter. Support value Perimeter feeds AWMSI. Alone it is sensitive to raster edge noise, so it should not drive interpretation without shape context.
npools / n_patches Count of connected wet components. Kept as number_of_pools Basic fragmentation signal. More pools can mean disconnection, but it depends strongly on resolution, connectivity rule, and minimum patch size.
AWMSI Area-weighted mean shape index. Kept Captures boundary complexity or crenulation. Matters because two reaches can have similar area but very different edge complexity and habitat geometry.
AWRe Area-weighted elongation ratio. Kept Captures whether wet patches are compact or elongated. Refactor records the length method because curved pools and major-axis pools can tell different stories.
AWMPA Area-weighted mean patch area. Dropped Weak independent signal. Patch-size dominance is better handled with fixed-denominator LPI and, if validated, MESH.
AWMPL Area-weighted mean pool length. Dropped Less useful than separating longitudinal extent and spacing. LPSEC tells how much channel is wet; inter-pool gap tells how isolated pools are.
AWMPW Area-weighted mean pool width. Dropped / reworked Original area-weighting over-emphasises large pools. Refactor prefers an unweighted width distribution with resolution-floor flags, not one headline weighted mean.
APSEC Wetted area as percent of section area. Kept as apsec Core extent metric. It answers: how much of the reference area is wet this month?
LPSEC Wetted length as percent of section length. Channel gated Useful longitudinal extent metric, but only defensible with a real L_ref and visible length-CRS caveat. Excluded from core no-channel output.
PF Pool count divided by current wetted area. Dropped Circular denominator. When wet area shrinks, PF can rise even if the ecological fragmentation process is not independently changing.
PLF / PFL Pool count divided by current wetted length. Dropped Same circularity problem as PF, now along length. Use fixed-reference LPSEC, LPI, and inter-pool gap instead.
pp_mean_% Mean pixel persistence above a legacy threshold. Replaced by occurrence Persistence is still important, but denominator must be valid observations, not total timesteps. This prevents clouds or missing wet-season observations from biasing persistence downward.
ra_area_km2 Area of highly persistent water pixels. Kept as refuge_area Direct refuge magnitude. Matters for identifying persistent aquatic habitat through dry periods, but threshold and valid-observation support must travel with the value.
Pixel Persistence raster Per-pixel wet frequency over the full record. Replaced by occurrence raster Still foundational for refuge mapping and zones. Refactor makes the denominator explicit and supports source-agnostic masks.

Updated HydroFragments Metrics

Metric Current status What it measures Why it matters
occurrence Core implemented Per-pixel wet frequency using valid observations. Foundation for persistence, refuges, and zones. More defensible than old PP because missing observations do not count as dry.
refuge_area Core implemented Area above the configured occurrence threshold. Measures persistent wet habitat magnitude, useful for dry-season refuge risk and prioritisation.
apsec Core implemented Monthly wetted area divided by fixed reference area. Clean surface-water extent measure. Comparable through time within the same AOI because denominator stays fixed.
number_of_pools Core implemented Count of connected wet patches after patch filtering. Simple fragmentation signal. Needs connectivity rule and minimum patch size metadata to be interpretable.
lpi Core implemented Largest wet patch area as percent of fixed landscape area. Shows whether wet habitat is dominated by one large connected patch or split into smaller pieces.
awre Core implemented Area-weighted elongation of wet patches. Shape axis for compact versus elongated pools. Matters for describing drying geometry, but interpretation should remain cautious until validated.
awmsi Core implemented Area-weighted boundary complexity. Captures edge complexity separately from elongation. Useful, but sensitive to raster resolution and edge noise.
recurrence Registered / deferred How often water returns after absence. Useful for distinguishing permanent pools, seasonal returns, and episodic reconnection patterns.
hydroperiod Registered / deferred Seasonal duration or timing of wet presence. Connects remote-sensed water presence to ecological exposure time and habitat availability.
extent_contraction Dynamics deferred Hydrological-year extent decline rate. Potential headline dry-down signal, but it needs HY anchors and composite-sensitivity checks before strong interpretation.
reconnection_timing Dynamics deferred Month or HY point when disconnected wet habitat reconnects. Important for fish movement, refuge escape, and environmental-flow timing. Needs a defensible connectivity metric.
refuge_spatial_stability Dynamics deferred Persistence of refuge locations between years. Separates stable refuge networks from shifting or unreliable wet patches.
lpsec Channel gated Wetted length divided by fixed channel length. Strong longitudinal extent measure, but depends on drainage context and length distortion caveats.
inter_pool_gap Channel gated Distance between pools along a channel reference. Better river-specific clustering metric than 2D nearest-neighbour distance because rivers are quasi-linear systems.
mesh Secondary Effective mesh size from patch-size distribution. Complements LPI if not redundant. Should be kept only if validation shows it adds information beyond largest patch dominance.
pool_width Secondary Distribution of planform pool widths. Potential morphology signal. Needs resolution-floor flags because 30 m masks can make narrow widths look more precise than they are.
realised_connectivity Connectivity gated Snapshot connection among wet nodes or reaches. Measures network function, not just patch size. Must state relationship to DCI, PC, and IIC literature.
tcf Connectivity gated Temporal connectivity frequency. Shows how often a reach is connected through time. Renamed from PCF to avoid confusion with Probability of Connectivity.

Dropped or Excluded Metrics

Metric Reason Better replacement or handling
PF Circular denominator: pool count over current wetted area. Use number_of_pools plus LPI/APSEC context.
PLF / PFL Circular denominator: pool count over current wetted length. Use LPSEC with real channel context, plus inter_pool_gap where available.
AWMPA Weak independent value beside fixed-denominator patch-size metrics. Use LPI and, if validated, MESH.
AWMPL Less informative than separate longitudinal extent and spacing. Use LPSEC and inter_pool_gap.
AWMPW Area-weighted mean hides width distribution and overweights large pools. Use unweighted pool_width distribution with mean, median, max, CV, and resolution warnings.
NNI 2D nearest-neighbour null is weak for a river corridor. Prefer inter_pool_gap along the channel. NNI is cut from canonical v1.2 IDs.
degree / betweenness centrality Too much graph machinery for little signal in linear reaches. Use realised_connectivity, TCF, or DCI-positioned metrics if a network analysis is needed.
PCF Name collides with Probability of Connectivity language. Use TCF for temporal connectivity frequency.

Why the Refactor Matters

Scientific punchline: HydroFragments is not just renaming columns. It changes the metric logic from broad legacy summaries toward a defensible register: fixed denominators, valid-observation denominators, explicit dependencies, and warning flags.

  • More trustworthy time comparisons: a changing wet area no longer silently changes the denominator for fragmentation metrics.
  • Better missing-data handling: occurrence and refuge calculations can distinguish dry pixels from unobserved pixels.
  • Clearer publication story: the strongest novelty is the metric-register reformulation and circularity critique, not simply another Gilbert-style case study.
  • Better manager interpretation: APSEC, refuge_area, number_of_pools, LPI, and dry-down metrics map more cleanly to questions about extent, refuges, fragmentation, and reconnection timing.
  • Less false precision: channel, width, connectivity, and HY metrics carry dependency gates and caveats instead of being emitted as if every input supports them.
